**Module-level state** for tracking inline Fastify instance:

let _fastifyInstance = null;

**Tool 1: trigger_import**
- inputSchema: `{ max_age_days: z.number().int().min(1).max(365).optional().describe('Max age of sessions to import in days (default: 2)') }`
- Handler: Call `await runImport(db, { maxAgeDays: max_age_days ?? 2, source: 'mcp' })`. On success, return `{ ok: true, ...result }`. Catch `ImportConflictError` and return `{ isError: true, content: [{ type: 'text', text: JSON.stringify({ error: 'already_running', message: err.message }) }] }`. Re-throw unexpected errors.
- Description: "Trigger a data import from Claude Code session files. Returns import stats on success or error if already running."

**Tool 2: start_server**
- No inputSchema (no parameters)
- Handler logic:
  1. Check if `_fastifyInstance` is already running in this process — if so, return its URL
  2. Check DB lock: `db.prepare('SELECT * FROM process_locks WHERE lock_name = ?').get('server')` — if lock exists and `isProcessAlive(lock.pid)`, return `{ status: 'already_running', url: 'http://127.0.0.1:' + lock.port, pid: lock.pid }`
  3. Otherwise start Fastify inline:
     - Dynamic import `../../server/index.js` for `createServer`
     - `const fastify = createServer(db, {})` — pass `logger: false` to suppress output (actually createServer already takes options, check if it passes logger config; if not, Fastify defaults are fine since MCP redirects nothing to stderr)
     - Listen with port fallback loop (same pattern as cli.js serve command, ports 3847-3856)
     - `claimLock(db, 'server', process.pid, 'mcp', actualPort)`
     - Store `_fastifyInstance = fastify`
     - Return `{ status: 'started', url: 'http://127.0.0.1:' + actualPort }`
  4. On listen failure, return `{ isError: true, content: [{ type: 'text', text: JSON.stringify({ error: 'start_failed', message: err.message }) }] }`
- Description: "Start the cctimereporter web server. Returns URL of existing server if one is running, or starts a new one."

**Tool 3: stop_server**
- No inputSchema
- Handler logic:
  1. Check DB lock for 'server'
  2. If no lock or process not alive: clean up stale lock if exists (`releaseLock`), return `{ status: 'not_running' }`
  3. If the running server is in THIS process (`lock.pid === process.pid`): close `_fastifyInstance` if set (`await _fastifyInstance.close()`), set `_fastifyInstance = null`, `releaseLock(db, 'server', process.pid)`, return `{ status: 'stopped', was_pid: lock.pid }`
  4. If running in ANOTHER process: send `process.kill(lock.pid, 'SIGTERM')`, wait briefly (small delay), `releaseLock(db, 'server', lock.pid)`, return `{ status: 'stopped', was_pid: lock.pid }`
  5. Wrap kill in try/catch — process may already be dead
- Description: "Stop the cctimereporter web server. Stops any running instance regardless of how it was started."

**Tool 4: server_status**
- No inputSchema
- Handler: Check DB lock for 'server'. If lock exists and `isProcessAlive(lock.pid)`, return `{ running: true, url: 'http://127.0.0.1:' + lock.port, pid: lock.pid, source: lock.source }`. Otherwise clean up stale lock and return `{ running: false }`.
- Description: "Check if the cctimereporter web server is running."

**Export a cleanup function** for use by server.js exit handler:
```javascript
export function cleanupMcpServer(db) {
  if (_fastifyInstance) {
    try { _fastifyInstance.server.close(); } catch(_) {}
    _fastifyInstance = null;
  }
  releaseLock(db, 'server', process.pid);
}
```
