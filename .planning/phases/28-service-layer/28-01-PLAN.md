Create a factory function `createTimelineService(db)` that returns an object with two methods:

**`getTimelineUI(date, { thresholdMin = 10 } = {})`** -- Returns the EXACT same response shape as the current `GET /api/timeline` handler, minus `schemaMigrated` (that stays in the route). Specifically returns `{ date, totalSessions, projects: [...] }` where each project has `{ projectId, projectPath, displayName, sessions }` and each session has all current fields including `idleGaps`, `forkSegments`, `continuesFromPrevDay`, `continuesIntoNextDay`, `elapsedTimeMs`.

Move the ENTIRE body of the current `fastify.get('/api/timeline', ...)` handler into this method, including:
- Day boundary computation (`dayStartUTC`, `dayEndUTC`)
- `sessionStmt.all()` query
- `allProjectPathsStmt.all()` lookup for worktree resolution
- Fork segment batch queries (dynamic IN clause -- keep `db.prepare()` inline for these, NOT pre-prepared)
- The session processing loop with clamping, working time, idle gaps, fork segments
- Project grouping via `projectMap`
- `totalSessionsStmt.get()` count

Import `computeWorkingTime`, `computeIdleGaps`, `getDisplayName`, `getWorktreeParentPath` from `../utils/timeline-utils.js`.

Keep `computeForkSegments` as a private function inside `src/services/timeline.js` (it uses `computeWorkingTime` from utils but is only needed by the UI projection).

Pre-prepare these statements in the factory body (outside the returned methods):
- `sessionStmt` (the main session query with subagent/worktree filter)
- `messageStmt` (timestamps for a session)
- `totalSessionsStmt` (COUNT of all sessions)
- `allProjectPathsStmt` (all project paths for worktree resolution)

The dynamic fork queries (`forkRowsBySession` and `forkTimestampsByBranch`) MUST remain inside `getTimelineUI()` using `db.prepare()` at call time because the IN clause placeholder count varies. Store `db` in the closure for this purpose.

**`getTimelineReport(date, { thresholdMin = 10 } = {})`** -- Returns a reporting projection for CLI/MCP consumption. Shape:
```javascript
{
  date: 'YYYY-MM-DD',
  workingTimeMs: Number,     // total across all sessions
  byTicket: [
    {
      ticket: 'PROJ-123',   // or null for unticketed
      workingTimeMs: Number,
      sessionCount: Number,
      projects: ['name1'],   // unique display names
      sessions: [
        {
          sessionId, project, ticket, branch,
          workingTimeMs, summary, startTime, endTime,
          userLabel, userTicket,
        }
      ]
    }
  ],
  unticketedSessions: [ ... ] // sessions where ticket is null
}
```

Implementation: Reuse the same underlying data fetch as `getTimelineUI` -- extract a private `_querySessions(date, thresholdMin)` helper that both methods call. This helper returns the raw session data with computed working time. `getTimelineUI` shapes it into the current project-grouped format. `getTimelineReport` groups by ticket (using `userTicket ?? ticket` as the key, preferring user override).

The `DEFAULT_IDLE_THRESHOLD_MIN` constant (value: 10) should be defined and exported from this service file.
