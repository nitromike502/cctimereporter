**1. Zoom level indicator (ZPOL-01):**
In the `.zoom-bar` template section, add a formatted zoom level display AFTER the NumberStepper showing the value with an "x" suffix. Use a computed or inline template expression: `{{ zoomLevel }}x`. Actually — re-examining the zoom bar, the NumberStepper already shows the numeric value (e.g. "2.5") in its input field. Adding a separate "2.5x" label next to it would be redundant. **2. Smooth CSS transition for button zoom only (ZPOL-02):**
The challenge: wheel zoom must be instant (cursor-anchor scrollLeft is set in nextTick, CSS transition would cause drift). Button zoom via NumberStepper can animate smoothly.

Approach — use a reactive ref `isTransitioning` (default false):
- Add a CSS class `zoom-transitioning` to `.gantt-canvas` when `isTransitioning` is true.
- In CSS: `.gantt-canvas.zoom-transitioning { transition: width 150ms ease-out; }`
- The NumberStepper emits `update:modelValue`. Currently GanttChart re-emits it to the parent. Intercept this: create a handler `onStepperZoom(val)` that sets `isTransitioning = true`, emits `update:zoomLevel`, then after 160ms sets `isTransitioning = false` via setTimeout.
- The wheel handler `onWheel` does NOT set `isTransitioning`, so wheel zoom remains instant.

Implementation detail for the stepper handler:
```javascript
const isTransitioning = ref(false)
let transitionTimer = null

function onStepperZoom(newZoom) {
  isTransitioning.value = true
  emit('update:zoomLevel', newZoom)
  clearTimeout(transitionTimer)
  transitionTimer = setTimeout(() => { isTransitioning.value = false }, 160)
}
```

Update the NumberStepper `@update:model-value` to call `onStepperZoom($event)` instead of directly emitting.

In the template, bind the class on `.gantt-canvas`:
`:class="{ 'zoom-transitioning': isTransitioning }"`

<task type="auto">
  <name>Task 2: Adaptive time axis tick density</name>
  <files>src/client/components/GanttChart.vue</files>
  <action>
Replace the static `timeAxisTicks` computed with a zoom-aware version that increases tick density at higher zoom levels.

**Tick density rules:**
- Zoom 1x-1.5x: every 2 hours (13 ticks) — current behavior
- Zoom 1.75x-2.5x: every 1 hour (25 ticks)
- Zoom 2.75x-3.5x: every 30 minutes (49 ticks)
- Zoom 3.75x-4x: every 15 minutes (97 ticks)

Implementation:
```javascript
const timeAxisTicks = computed(() => {
  const z = props.zoomLevel
  // Determine step in hours based on zoom level
  let stepHours
  if (z >= 3.75) stepHours = 0.25      // 15 min
  else if (z >= 2.75) stepHours = 0.5   // 30 min
  else if (z >= 1.75) stepHours = 1     // 1 hour
  else stepHours = 2                     // 2 hours

  const ticks = []
  for (let h = 0; h <= 24; h += stepHours) {
    const pct = (h / 24) * 100
    const totalMinutes = h * 60
    const hours = Math.floor(totalMinutes / 60)
    const minutes = Math.round(totalMinutes % 60)

    let label
    if (minutes === 0) {
      // Full hour — use 12-hour format
      const h12 = hours === 0 ? 12 : hours > 12 ? hours - 12 : hours
      const suffix = hours < 12 || hours === 24 ? 'a' : 'p'
      label = `${h12}${suffix}`
    } else {
      // Sub-hour — show as "H:MM" in 12-hour format
      const h12 = hours === 0 ? 12 : hours > 12 ? hours - 12 : hours
      const suffix = hours < 12 ? 'a' : 'p'
      label = `${h12}:${String(minutes).padStart(2, '0')}${suffix}`
    }
    ticks.push({ pct, label })
  }
  return ticks
})
```

This replaces the existing `timeAxisTicks` computed entirely. The key change is that `props.zoomLevel` is now a dependency, so ticks recompute when zoom changes.

No changes needed to the template — it already iterates `timeAxisTicks` for both the time axis and grid overlay.
