Add fork_branch_id column to the messages table (schema v7) and populate it during import so each distinct fork branch has a unique, stable identifier.

Purpose: Fork visualization (Phase 23-25) needs per-branch identity to compute fork segments and render distinct fork bars. Without fork_branch_id, all fork messages are a flat boolean — no way to distinguish which branch a message belongs to.

Output: Schema v7 with fork_branch_id column, fork detector that assigns branch IDs, and db-writer that persists them.
</objective>

  Implementation:
  1. Add `const forkBranchMap = new Map();` alongside the existing `forkBranchUuids` Set.
  2. In the "Mark all secondary branch descendants as fork branches" loop (lines 84-96), after computing `branchInfo` and sorting by descendant count descending:
     - For each secondary branch child (branchInfo.slice(1)):
       - The branch ID is `childUuid` (the first message of that branch — already the fork point's direct child).
       - Walk all descendants of that childUuid (the existing DFS loop) and for each `current` UUID, set `forkBranchMap.set(current, childUuid)`.
     - Keep the existing `forkBranchUuids.add(current)` call too — it stays for backward compat.
  3. Also handle the PRIMARY branch at each fork point: the primary branch (branchInfo[0], largest descendant count) should NOT get a fork_branch_id. Its messages stay on the main timeline. Only secondary branches get IDs.
