Detailed implementation:

**Imports (after version check):**
```javascript
const { Command } = await import('commander');
const { openDatabase } = await import('../src/db/index.js');
const { summaryCommand } = await import('../src/cli/commands/summary.js');
const { sessionsCommand } = await import('../src/cli/commands/sessions.js');
const { importCommand } = await import('../src/cli/commands/import.js');
```

**Program setup -- read version dynamically from package.json:**
```javascript
import { readFileSync } from 'node:fs';
import { fileURLToPath } from 'node:url';
import { join, dirname } from 'node:path';

const __dirname = dirname(fileURLToPath(import.meta.url));
const pkg = JSON.parse(readFileSync(join(__dirname, '..', 'package.json'), 'utf8'));

const program = new Command();
program
  .name('cctimereporter')
  .description('Visual timeline of Claude Code sessions')
  .version(pkg.version);
```

IMPORTANT: Do NOT hardcode the version string. Read it from package.json so it stays in sync across releases. Use readFileSync + JSON.parse (not import assertion) for maximum Node.js compatibility.

**--debug-import as program option:**
Register as a program-level option so Commander doesn't error on it:
```javascript
program.option('--debug-import [on_off]', 'Enable/disable import debug logging');
```

Handle it via a `program.hook('preAction')`:
```javascript
program.hook('preAction', (thisCommand) => {
  const opts = program.opts();
  if (opts.debugImport !== undefined) {
    // Handle debug import logic (same as current lines 26-49)
    // Then process.exit(0) to stop further execution
  }
});
```

Wait -- the preAction hook runs before each subcommand action too. Better approach: handle --debug-import BEFORE parseAsync, using `program.hook('preSubcommand')` or by checking process.argv manually (as currently done) but ALSO registering the option with Commander so it doesn't error. Actually the simplest approach that preserves current behavior:

1. Register `--debug-import [value]` as a program-level option (so Commander accepts it)
2. Keep the existing manual argv check block BEFORE `program.parseAsync()` -- if --debug-import is found, handle it and exit(0) before Commander even runs
3. This way Commander never errors on the flag, and the handling stays simple

**Register subcommands:**
```javascript
const { db } = openDatabase();

program.addCommand(summaryCommand(db));
program.addCommand(sessionsCommand(db));
program.addCommand(importCommand(db));
```

**Serve command (isDefault: true):**
Create the serve command inline (the server startup logic). Extract the current server startup code (lines 54-113 of current cli.js) into the action handler of a `serve` command marked `{ isDefault: true }`:

```javascript
const serve = new Command('serve')
  .description('Start web server and open browser (default)')
  .option('--port <port>', 'Port to listen on', '3847');

serve.action(async () => {
  // All current server startup logic goes here:
  // createServer, port fallback loop, claimLock, browser open, signal handlers
  // Use dynamic imports for server-only deps:
  const { createServer } = await import('../src/server/index.js');
  const { spawn } = await import('node:child_process');
  const { claimLock, releaseLock } = await import('../src/services/coordination.js');
  // ... rest of server logic
});

program.addCommand(serve, { isDefault: true });
```

Move the server-only imports (createServer, spawn, readConfig for non-debug, claimLock/releaseLock) into the serve action handler so they only load when the server actually starts. The CLI subcommands should NOT load Fastify.

**Important details:**
- readConfig/writeConfig import must stay available for the --debug-import block (before Commander). Import it at the top alongside openDatabase.
- The serve command's action handler needs `migrated` from openDatabase -- pass it through. Actually openDatabase() returns `{ db, migrated }`. Destructure both at the top.
- Signal handlers (SIGINT/SIGTERM) belong inside the serve action (they reference fastify and db).
- The `db.close()` call needs to happen on errors in subcommands too. Wrap the parseAsync in try/finally or use `program.hook('postAction')`.

**DB cleanup:** Add a postAction hook or process 'exit' handler to close db:
```javascript
process.on('exit', () => { try { db.close(); } catch (_) {} });
```
This is safe because the serve command's signal handlers already call db.close() + process.exit(0), and for CLI commands the process exits naturally after the action completes.

**parseAsync:**
```javascript
await program.parseAsync(process.argv);
```

This must be the last line. Commander dispatches to the matched subcommand's action handler.
