# Phase 27 Plan 01: Messages Modal from DB

## Objective

Update the messages API and modal to read from the SQLite database instead of
scanning JSONL files. Add fork-branch filtering so that selecting a fork bar
shows only that branch's messages.

## Context

Phase 26 added a `content TEXT` column to the messages table. User and assistant
messages now have their text stored in the DB. The current messages route still
opens JSONL files from disk. The modal currently has no fork awareness.

Key DB columns available:
- `uuid` — message UUID
- `type` — 'user' or 'assistant'
- `content` — extracted, cleaned text (NULL for system/tool/progress)
- `timestamp` — ISO string
- `is_fork_branch` — boolean: 1 = secondary fork branch
- `fork_branch_id` — TEXT: NULL for primary branch; set for secondary branches

## Tasks

### Task 1: Update messages API to serve from DB
**type="auto"**

Rewrite `src/server/routes/messages.js`:
- Remove all JSONL file reading code (fs, readline imports)
- Query messages table using session_id WHERE content IS NOT NULL
- Support optional `?forkBranchId=X` query param:
  - If provided: WHERE fork_branch_id = forkBranchId (that specific fork branch only)
  - If not provided: WHERE (fork_branch_id IS NULL OR fork_branch_id = '') (primary branch only, i.e. is_fork_branch = 0)
  - Special value `?forkBranchId=all`: return all messages regardless of fork_branch_id
- Order by timestamp ASC
- Return head/tail split (first 10, last 10) with skipped count — same as before
- Response shape: `{ messages, totalCount, skipped }`
- Each message: `{ uuid, role, content, timestamp, is_fork_branch, fork_branch_id }`
  - `role` derived from `type` column: 'user' or 'assistant'

**Done when:** GET /api/sessions/:id/messages returns messages from DB. GET /api/sessions/:id/messages?forkBranchId=X returns only that fork branch's messages.

### Task 2: Update SessionMessagesModal to use DB data + fork filtering
**type="auto"**

Update `src/client/components/SessionMessagesModal.vue`:
- Add `forkBranchId` prop (String, default '')
- When `forkBranchId` is set, include `?forkBranchId={forkBranchId}` in fetch URL
- Update modal title: if forkBranchId is set, show "Fork Branch Messages" instead of "Session Messages"
- Add fork badge/subtitle under title: "Showing messages from fork branch {id.slice(0,8)}..." when filtered
- Keep existing conversation rendering (user/assistant role labels, expand/collapse, head/tail split)
- Add timestamp display next to role label (format: HH:MM AM/PM)

Update `src/client/pages/TimelinePage.vue`:
- Add `messagesModalForkBranchId` ref (default '')
- Update `@show-messages` handler on SessionDetailPanel to clear fork context
- Add `show-messages` event to fork view in `SessionDetailPanel.vue`:
  - Add "view messages" link in fork detail grid (similar to session view)
  - Emit `show-messages-fork` with `fork.forkBranchId`
- In TimelinePage, handle `@show-messages-fork` on SessionDetailPanel:
  - Set `messagesModalForkBranchId = fork.forkBranchId`
  - Set `messagesModalOpen = true`
- Pass `:fork-branch-id="messagesModalForkBranchId"` to SessionMessagesModal
- Reset `messagesModalForkBranchId` when modal closes (watch open → false)

**Done when:** Clicking "view" on a session opens the modal with that session's primary-branch messages. Clicking "view messages" on a fork bar opens the modal filtered to that fork branch. Modal title/subtitle changes to reflect fork context.
