## v0.7.0 Requirements

All 19 requirements shipped.

### Schema & Import — Forks
- [x] **SCHM-01**: Messages table has `fork_branch_id` column
- [x] **SCHM-02**: Schema auto-migrates adding `fork_branch_id` column
- [x] **SCHM-03**: Fork detector populates `fork_branch_id` during import

### Backend — Fork Segments
- [x] **FSEG-01**: Timeline API returns fork segment data with working time
- [x] **FSEG-02**: Each fork segment has start time, end time, fork branch ID, workingTimeMs, elapsedTimeMs
- [x] **FSEG-03**: Sessions without forks return unchanged

### Frontend — Gantt Rendering
- [x] **GANT-01**: Fork branches displayed as 50% height sub-bars
- [x] **GANT-02**: Each fork bar starts at fork point timestamp
- [x] **GANT-03**: Fork bars visually distinct (lighter opacity, highlighted when selected)
- [x] **GANT-04**: Sessions without forks render unchanged

### Frontend — Interaction
- [x] **INTR-01**: Clicking a fork bar opens detail panel with fork-specific info
- [x] **INTR-02**: Show/hide toggle for fork sub-rows (localStorage persisted)

### Frontend — Detail Panel
- [x] **DETL-01**: Detail panel shows fork working time, elapsed time, start/end, messages with parent session context

### Schema & Import — Stored Messages
- [x] **MSGS-01**: Messages table has `content` column (1000 char truncation, 1250 buffer)
- [x] **MSGS-02**: Schema v8 auto-migrates adding `content` column
- [x] **MSGS-03**: Importer populates `content` for user/assistant only, XML stripped

### Messages Modal
- [x] **MODL-01**: Messages modal reads from DB instead of JSONL files
- [x] **MODL-02**: Fork messages filtered by fork_branch_id when fork bar selected
- [x] **MODL-03**: Messages display with role labels and timestamps

**Shipped:** 19 of 19 requirements
