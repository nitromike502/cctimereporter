## Milestone Summary

**Key Decisions:**
- fork_branch_id = first child UUID of secondary branch (stable across re-imports)
- Progress forks filtered via isProgressBranch() tree walk — only real user forks shown
- Fork bars overlay in lower half of existing row (avoids label-height sync pitfall)
- Fork segments computed at query time (import raw, derive at query time philosophy)
- Message content: text blocks only, XML stripped, 1000 char truncation with 1250 buffer
- Fork working time computed with same computeWorkingTime() algorithm as sessions
- Messages modal switched from JSONL file reading to DB queries

**Issues Resolved:**
- Progress forks (assistant → [progress, user]) incorrectly classified as real forks
- Fork segment timestamps outside day boundaries (startTime > endTime)
- Detail panel layout shift when switching between session and fork selection
- Fork modal showing 0 messages (wrong session ID passed)
- 1-message fork bars cluttering the UI (filtered to ≥2 messages)

**Technical Debt Incurred:**
- DEFAULT_BRANCHES set duplicated in GanttBar.vue and ticket-scorer.js
- Fork working time uses all message timestamps (not just user/assistant)
