# Requirements: CC Time Reporter v1.1.0

**Defined:** 2026-04-07
**Core Value:** A user runs one command and immediately sees a clear visual timeline of their Claude Code sessions for any given day

## v1.1.0 Requirements

Requirements for token usage tracking and visualization.

### Data Storage

- [x] **DATA-01**: Store input_tokens, output_tokens, cache_creation_input_tokens, cache_read_input_tokens per assistant message in schema v10 — *Validated, Phase 32*
- [x] **DATA-02**: Store ephemeral cache tier sub-fields (ephemeral_5m_input_tokens, ephemeral_1h_input_tokens) per assistant message — *Validated, Phase 32*
- [x] **DATA-03**: Store model name per assistant message — *Validated, Phase 32*
- [x] **DATA-04**: Schema auto-migrates from v9 to v10 — *Validated, Phase 32*
- [x] **DATA-05**: Historical sessions backfilled with token data via re-import — *Validated, Phase 32*

### Token Display

- [x] **DISP-01**: Session detail panel shows input/output/cache token breakdown — *Validated, Phase 33-02*
- [x] **DISP-02**: Session detail panel shows cache hit rate percentage — *Validated, Phase 33-02*
- [x] **DISP-03**: Day summary panel shows total tokens for the day — *Validated, Phase 33-02*
- [x] **DISP-04**: CLI `summary` command includes token totals in JSON output — *Validated, Phase 34-01*
- [x] **DISP-05**: CLI `sessions` command includes per-session token totals — *Validated, Phase 34-01*
- [x] **DISP-06**: MCP `get_day_summary` tool includes token totals — *Validated, Phase 34-01*
- [x] **DISP-07**: MCP `get_sessions` tool includes per-session token totals — *Validated, Phase 34-01*

### Chart Page

- [x] **CHART-01**: New `/tokens` page accessible via app navigation — *Validated, Phase 35-01*
- [x] **CHART-02**: Date navigation on tokens page (reuse timeline toolbar pattern) — *Validated, Phase 35-01*
- [x] **CHART-03**: Line chart with one line per session, x-axis is time of day — *Validated, Phase 35-02 (x-axis evolved from message-index spec to time-of-day for better UX)*
- [x] **CHART-04**: Aggregate "all sessions" combined line on the chart — *Adjusted, Phase 35-02 (substituted with Session Totals stacked bar chart toggle; literal aggregate overlay line on Per Message view not implemented)*
- [x] **CHART-05**: Toggle between cumulative and per-message chart views — *Adjusted, Phase 35-02 (renamed to "Session Totals ↔ Per Message"; semantic intent preserved — aggregated vs time-bucketed view)*
- [x] **CHART-06**: User can show/hide individual session lines — *Adjusted, Phase 35-02 (implemented as per-project visibility checkboxes; sessions in same project cannot be individually toggled)*

### Bonus Scope (added mid-milestone)

- [x] **DRILL-01** *(implicit, added 2026-04-10)*: Double-clicking a Per Message chart bucket opens a modal showing messages from that time range with inline token counts — *Validated, Phases 36-01 and 36-02*

## Out of Scope

| Feature | Reason |
|---------|--------|
| Real-time / live token counter | CC Time Reporter is retrospective; competes with Claude Code `/cost` command |
| Dollar cost as primary metric | Most users are Max plan subscribers; API-rate pricing is misleading |
| Budget alerts and spend caps | Requires persistent monitoring infrastructure; use Anthropic Console |
| Per-tool-call token attribution | JSONL `usage` is per-message, not per-tool-call; no reliable source data |
| ML-based usage predictions | Historical tool; leave predictions to live monitors |
