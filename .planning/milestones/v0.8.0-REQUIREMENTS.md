## v0.8.0 Requirements

### Service Layer

- [x] **SVC-01**: Timeline query logic extracted from route handlers into `src/services/` modules callable by routes, CLI, and MCP
- [x] **SVC-02**: Import orchestration extracted into service layer with progress callback support
- [x] **SVC-03**: DB-based server ownership coordination — process registers PID/port in SQLite, other processes detect and defer
- [x] **SVC-04**: DB-based import lock — process registers import-in-progress in SQLite, other processes reject concurrent imports with clear message

### MCP Server

- [x] **MCP-01**: `npx cctimereporter --mcp` starts a stdio MCP server (using @modelcontextprotocol/sdk)
- [x] **MCP-02**: `get_day_summary` tool returns sessions grouped by project with working time, tickets, and branches for a given date
- [x] **MCP-03**: `get_sessions` tool returns full session list with start/end, ticket, branch, project, working time, and idle gaps for a given date
- [x] **MCP-04**: `get_session_messages` tool returns message content for a specific session ID
- [x] **MCP-05**: `trigger_import` tool runs import with optional maxAgeDays parameter, respects DB-based import lock
- [x] **MCP-06**: `start_server` tool starts Fastify web server if not already running; returns URL if already running from another session
- [x] **MCP-07**: `stop_server` tool stops the web server — kills owning process if stuck, clears stale ownership
- [x] **MCP-08**: `server_status` tool reports whether web server is running, which PID owns it, and on what port

### CLI Subcommands

- [x] **CLI-01**: `npx cctimereporter summary --date YYYY-MM-DD` outputs JSON day summary to stdout
- [x] **CLI-02**: `npx cctimereporter sessions --date YYYY-MM-DD` outputs JSON session list to stdout
- [x] **CLI-03**: `npx cctimereporter import [--days N]` runs import without starting server, respects DB lock, progress to stderr
- [x] **CLI-04**: `npx cctimereporter` with no subcommand starts web server and opens browser (backward compatible)

### Multi-Instance Coordination

- [x] **COORD-01**: Multiple MCP server instances can read from the same SQLite database concurrently without conflict
- [x] **COORD-02**: Only one web server instance runs at a time — first to claim port wins, others detect and report existing URL
- [x] **COORD-03**: Only one import runs at a time across all instances — DB lock with PID and timestamp, stale lock detection
- [x] **COORD-04**: Stale process detection — if owning PID is dead, ownership/lock is automatically reclaimed
